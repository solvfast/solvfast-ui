## Phase 2 — outcomes
1. **Metadata-driven Lead editors in mock mode.**
   - The Lead Profile and Lost Reason editors are the shared `FrappeField`, driven by the Lead DocType meta (the meta is
     imported directly; +7 kB gzip).
   - `FrappeLocalForm` (package, Frappe layer) runs FrappeField with no server:
     - Link search, validate_link and get_link_title run locally over rows the host supplies;
     - every other call is refused, never retried, and no network call happens (asserted);
     - `useFormCapabilities()` says what local mode cannot do.
   - `CrmMockLinkInput` is retired. Mock save keeps the server's Email / Phone / non-negative messages.
2. **Priority.** Visible in Desk (not hidden, no depends_on, permlevel 0), so it was added in both modes through
   FrappeField.
3. **Lead parity.**
   - The simulator refuses invalid Email / Phone / Name / URL / IBAN, negative `non_negative` values and over-length
     values with Frappe's messages (`_validate_data_fields`, `_validate_non_negative`, `_validate_length`).
   - Header rename: a one-word English name is refused with Desk's "Missing Fields … Last Name". In simulated mode it
     saves the Frappe document.
   - Display and labels:
     - the phone row's label is now "Mobile";
     - revenue shows `$ 32,000,000.00` (Desk's format_currency);
     - Lead Type shows its title (a "Serve Fast CRM Type" meta seeded; mock mode uses local get_link_title);
     - Lead Source shows its label through `__()` translation.
   - Prerequisites are editable on Frappe data.
   - The Outbound chip's dark-mode contrast went from 1.60 to about 18 (Lead page only).
4. **Light-mode glass.** Unchanged, as decided.
5. **Missing field types.**
   - **Signature:** Core `SignatureInput`. **Complete.**
   - **Icon:** `IconInput` / `FrappeIconField`. **Partial**: glyphs only where the page carries Desk's sprite.
   - **Barcode:** display only. **Partial**: editing needs `jsbarcode` 3.11.x (MIT), an owner decision.
   - **Geolocation:** display only. **Partial**: drawing needs Leaflet 1.2.0 (BSD-2) + Leaflet.draw 0.4.12 (MIT), an
     owner decision.
   - No existing consumer uses any of the four.
6. **Print** (owner follow-up).
   - Core: `PrintView`, `PrintDocumentsDialog`, `composePrintDocument`, `printHtmlDocument`. Frappe: `FrappeFormPrint` and
     `FrappePrintDialog` now render these, with unchanged behaviour.
   - CRM mock adapter: Print Formats in mock metadata, Letter Heads, a local renderer, one print builder per entity.
   - Record print = the DS print view.
   - The list's selection Print = Desk's "Print Documents" dialog: Letter Head, Print Format, Page Size + Custom. Each
     selected document is rendered in the chosen format, one per page, previewed, then printed by the browser.
   - No Background Print, PDF or Full Page in mock mode (no server; the browser's "Save as PDF" covers PDF).
7. **Submittable Proposals** (owner follow-up: "Lifecycle drives docstatus").
   - Docstatus per status: Draft 0, Sent 1, Approved 1, Rejected 2, Expired 2.
   - Lifecycle actions submit or cancel. A mandatory field blocks submit with Desk's message; 1 → 0 is refused; only
     allowed fields change after submit.
   - Cancelled proposals can be amended (`<number>-1` with `amended_from`).
   - The list shows lifecycle actions, never plain Submit / Cancel (Desk with a workflow). Bulk Edit and Delete apply by
     docstatus.
   - The rules are Core pure functions (`src/record/docstatus.ts`). The simulator enforces them (`withSubmitRules`).

## Phase 3 — CRM reconciliation (another session edits the live CRM)
The live tree (`apps/serve_fast`) is not a git repository, and its last recorded deploy is `127c0b4` (P34). Another
session (and at least one more) changed it afterwards.

**Steps:**
- Snapshots copied live's `frontend/src` READ-ONLY onto branch `crm/live-20261109`, based on `127c0b4`:
  - 2026-11-09T15:24:23Z: 29 paths;
  - 2026-11-09T17:54:14Z: a 33-path delta, taken after that session reported its integration build green.
- Each snapshot was merged into `crm/p36e-int`. **Both sides were kept; nothing was reverted.**

**Conflicts and decisions:**
- **`PrerequisiteFormFields.tsx`:** P36d's Data attributes and live's `NoMockFileUploadContext` are independent; both
  kept.
- **`NewTaskWorkspace.tsx`:** live rewrote the form (typed one-step create). Its embedded mode already has no solid fill
  (P36d's goal), so live's version was kept.
- **Auto-merged with both sides:**
  - Lead / Deal detail pages (live added `recordLabel`, `recordType` / `recordId`);
  - `CrmAppLayout`;
  - `AppConfigurationPage`.
- **Dependency:** live added `@dagrejs/dagre` ^3.1.3 (MIT) for its lifecycle diagram. It was taken with live's exact
  lockfile entries.
- **Not taken (owner decision):** live's `@solvfast/ui` pin
  (`file:vendor/solvfast-ui-0.7.0-dev.5-dc60443.tgz`, set by another session) and `index.html`.
- **Owner decision "keep Service Desk as live":**
  - Live's Tickets app now provides the DS scope.
  - CRM-designed DS branches in shared components are therefore gated on the new `useCrmDsScope()`: the ⋯ menu
    shortcuts, the configuration pickers, the unsaved-changes dialog, the history times and avatars, the prerequisite
    attributes, the list's bulk tags and the Print Documents dialog.

**Result:** of the files live changed since `127c0b4`, 47 are byte-identical to live and 5 carry both sides. Service
Desk / Service Management screenshots against live's own build: 167 identical; 5 differ by 1–2 px (noise).

**Findings reported to the live session (not ours to fix there):**
- create-Deal regression check fails on live's own build;
- the Lifecycle card lost `aria-current="step"`;
- earlier-step dates drift after a transition (it confirmed the bug and is fixing it).

## Remaining limitations
- **Not native Frappe yet:**
  - Partial field types (27): see FIELD-TYPES.md. Notable: Date / Datetime have no typed entry and cannot be cleared;
    Datetime is not converted between user and system time zones; the Phone fieldtype has no country picker or
    `phonenumbers` check.
  - Barcode editing and Geolocation drawing need the dependencies listed above (owner approval).
- **Mock mode cannot:** check permissions, run custom Link queries, Create New from a Link, upload files, or render
  server print formats / PDF.
- **Behaviour differences:**
  - Mock Amend saves the new draft at once (Desk opens an unsaved copy).
  - Arabic mock Link titles show the Arabic record names (simulated mode shows the title field, as Desk does).
- **Real-site validation:** Pending. No isolated staging site, accounts or approval file.
