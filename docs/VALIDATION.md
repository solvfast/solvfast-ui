### The two path A / path B differences (mobile 390 px, English, sheet open)
Text edges and the sheet's 1-px right edge differ (max 82/255 light, 126/255 dark). Investigation:
1. **It follows the stylesheet**: B's page with A's CSS renders exactly like A, and vice versa. Fonts loaded: identical.
2. **Not a style or layout difference**: computed styles of all 182 elements and their `::before`/`::after` are identical
   (one exception, fixed: path B's scoped preflight missed `<html>`'s own `::before`/`::after`, which have no content
   and don't render); text boxes identical to 0.001 px; no running animations.
3. **The two stylesheets differ only** in the 42 scoped preflight rules and in where path B's app CSS and opt-in base
   rules sit; moving those to path A's positions does not remove the difference.
4. **It is the sheet's fractional origin**: the sheet is 75 % wide and anchored right, so at 390 px its left edge is at
   97.5 px. At viewport widths where that edge is a whole pixel (388, 392, 400 px) A and B are identical (dark: one pixel
   at 10/255 in the blurred backdrop). At 393 px (edge 98.25 px) it differs again. Arabic (sheet at x = 0) never differs.
   Disabling sub-pixel glyph positioning or GPU raster does not change it.

**Conclusion**: Chrome rasterises the glass sheet layer with a half-pixel offset that depends on how the page's
stylesheet is composed — a rendering-engine effect, not a CSS value difference. No reliable fix exists in the package
without changing the sheet's geometry (Sear's design), so none was applied. Limitation documented in CONSUMING.md.

### Button motion (measured in the browser, package vs Sear)
| Variant | Rest | Pressed | Reduced motion |
|---|---|---|---|
| default, secondary, outline, ghost, destructive | 0.4 s (colour, shadow), 0.26 s (movement) | 0.16 s | none |
| ai-outline | 0.18 s | 0.12 s (Sear: 0.18 s) | none |

The documented 180/120 ms govern `ai-outline` (and Calendar's `text` day buttons). The five glass variants run on
the glass engine's own timings — **identical to Sear**: the engine's transition rule loads after Tailwind's duration
utilities and wins, in Sear as in the package. Making 180/120 apply to glass buttons would change how every Sear
button feels; left as a design decision.
