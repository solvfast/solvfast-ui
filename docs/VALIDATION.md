### The two path A / path B differences (mobile 390 px, English, sheet open)
Text edges and the sheet's 1-px right edge differ (max 82/255 light, 126/255 dark). Investigation:
1. **It follows the stylesheet**: B's page with A's CSS renders exactly like A, and vice versa. Fonts loaded: identical.
2. **Not a style or layout difference**: computed styles of all 182 elements and their `::before`/`::after` are identical
   (one exception, fixed: path B's scoped preflight missed `<html>`'s own `::before`/`::after`, which have no content
   and don't render); text boxes identical to 0.001 px; no running animations.
3. **The two stylesheets differ only** in the 42 scoped preflight rules and in where path B's app CSS and opt-in base
   rules sit; moving those to path A's positions does not remove the difference.
4. **It is the sheet's fractional origin**: the sheet is 75 % wide and anchored right, so at 390 px its left edge is at
   97.5 px. At viewport widths where that edge is a whole pixel (388, 392, 400 px) A and B are identical (dark: one pixel
   at 10/255 in the blurred backdrop). At 393 px (edge 98.25 px) it differs again. Arabic (sheet at x = 0) never differs.
   Disabling sub-pixel glyph positioning or GPU raster does not change it.

**Conclusion**: Chrome rasterises the glass sheet layer with a half-pixel offset that depends on how the page's
stylesheet is composed — a rendering-engine effect, not a CSS value difference. No reliable fix exists in the package
without changing the sheet's geometry (Sear's design), so none was applied. Limitation documented in CONSUMING.md.

**The 8 intended differences** (column manager open, and after showing "Created By"; 4 combinations each). Sear's
Field Library declares its row actions as an `actions` field, so the column manager lists "Actions", a column shown
later is appended after it, the filter field list offers "Actions", and its header is a sort button that sorts
nothing. The approved bug list makes row actions a fixed last column. Evidence (Sear and package, lossless):
`docs/validation/5.3/actions-column/`.

**Not compared.** Sear's filter field list also offers ID, Created On and Last Updated, added by its Frappe metadata
helper (`frappe-meta.ts`); they arrive with the Frappe layer (5.4). In Sear's client mode those rows carry no creation
or modification date, so the two date filters cannot match anything there.

**Found while testing.** V8's `Date.parse` accepts strings like "Task 10" (October 2001) and "Room 101" (the year
101), so Sear's comparator sorted ordinary text containing a number as dates. The package compares only `Date` objects
and ISO / Frappe date strings as dates.

## After the 5.3 review (2026-10-15)

### Glass button motion: 180 ms / 120 ms
The DS Button documents hover 180 ms and press 120 ms (`design_system/frontend/src/components/ui/button.tsx:10`,
v0.3.0) and carries the matching classes; on glass variants the glass engine's later `.sf-glass` transition overrode
them (0.4 s / 0.26 s, pressed 0.16 s) — in Sear and in 5.1–5.3. A package rule (`styles/src/sf-fixes.css`,
specificity over the engine, duration only) restores the documented values on elements built from `buttonVariants`
(marker class `sf-button`).
