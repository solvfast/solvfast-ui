## 5. Verdict

The package's List View reproduces Desk's data path (rows, count, columns, filters, saved filters, user settings, list
settings, realtime), the server-authorised **Import** and **Export** request sequences with Desk's exact methods and
argument shapes, Desk's client-side gates for both (`canImport`, `canExport`), and the field picker of the Export dialog.
All of that is verified against stub transports only; Import and Export have NOT run against a site (BLOCKED: writes /
an unapproved read) and must not be described as verified on Frappe.

It is **not** a Frappe-compatible List View yet. Important behaviours still missing or deliberately different:

1. **Import UI**: no preview grid and no column-mapper (`import_preview.js`, 358 lines); no import-log table; progress by
   polling, not realtime. The functions exist (`startDataImport`, `useImportStatus`, `getImportLogs`,
   `downloadErroredRows`); the host must build the screens or route to Desk (`onImport` default).
2. **Export**: hidden without the `export` right where Desk shows it to everyone (rule D.1 — owner decision); the
   "Filtered Records" option uses the list's filters instead of an in-dialog FilterGroup; no record-count message; the
   Report-view export (`export_query`, Access Log) is not reproduced.
3. **Actions menu**: Print, Clear Assignment, Apply Assignment Rule, Add Tags and workflow bulk approval are missing.
4. **Columns**: no width-based cap; permlevel filtering needs the session's roles (without them the unreadable column
   header is still offered — the server strips the values).
5. **Filters / views**: nested-set operators, URL route filters, the group-by sidebar, Report / Kanban / Calendar views.
6. **Message keys**: the new labels (Import, Export, the dialog) are English with a `labels` / `ioLabels` override; the
   catalogue (`src/theme/messages.ts`) was outside this agent's scope.
