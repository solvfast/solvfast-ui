# Phase 27 decisions — review (Phase 27.5, 2026-11-03)

Four choices the Lead made in Phase 27 without owner input, reviewed against Frappe 15.110 source, the DS conventions,
permissions and usability. Evidence class of every test cited here: **simulated** (stubs / the in-package simulator).

| # | Decision | Frappe 15.110 | Review | Outcome |
|---|---|---|---|---|
| 1 | Width-based column limit **on by default** in `FrappeListView` | Desk always caps the columns it generates: 4 at ≤1366 px, 6, 10 at ≥1920 px; List View Settings `total_fields` wins (`public/js/frappe/list/list_view.js:432-444`). | Parity is the reason for the default. Capped columns are **hidden, not dropped** (`capDefaultColumns`, `src/frappe/list/settings.ts:109-135`): the column manager still offers them, as Desk's List Settings does. App-curated `columns` are never capped. No permission effect (the server strips unreadable values either way). Risk: a 0.3.x consumer relying on generated columns sees fewer at first; `columnLimit={false}` restores them; release notes say so. | **Keep.** |
| 2 | "Export as report" in the list's ⋯ menu | Desk's List View has **no** such entry; report-view export (`export_query`) lives in the Report view, gated by `frappe.model.can_export` (`views/reports/report_view.js:1646`). Desk's list offers only the Data Exporter (`list_view.js:2075-2092`). | A product addition beyond parity, and on a real site every `export_query` call writes an Access Log row (`desk/reportview.py:410-415`). Showing it by default would silently add behaviour the owner never asked for. | **Adjusted: opt-in.** `menu={{ reportExport: true }}` shows it (still gated by `canExport`); default off. Functions and `FrappeReportExportDialog` stay exported. Test: `list-io` "opt-in only (Phase 27.5)". |
| 3 | Disabled "No workflow action applies…" row when the server returns no common actions | Desk adds every transition as a workflow item, disables them while `get_common_transition_actions` is pending, then hides the ones not returned (`list_view.js:1832-1853`); with none returned, no workflow item is visible inside the shared Actions dropdown. | The package shows workflow actions in their own "Workflow" button (the actions are bar buttons, not Desk's single dropdown). An empty dropdown from that button would look broken; one disabled, explanatory item is the DS convention for an empty menu and runs nothing. No permission effect: the list comes from the server, computed for the session user. | **Keep** (documented difference). |
| 4 | Arabic labels of the nested-set operators | Desk shows Frappe's `ar` catalogue strings: "أحفاد من", "أحفاد (شاملة)", "ليس من أحفاد", "أجداد", "ليس الأجداد من". The English labels are Desk's exactly ("Descendants Of", …). | Frappe's Arabic is a literal genealogy translation ("grandchildren / grandparents") and one string is ungrammatical ("ليس الأجداد من"). In a tree DocType (Territory, Item Group, Department) the meaning is branches and parents: "من فروع" / "من فروع (مع العنصر نفسه)" / "ليس من فروع" / "من أصول" / "ليس من أصول" is clear and grammatical. Only the label differs; the operator sent to the server is Desk's. | **Keep** (English = Desk; Arabic = clearer wording, documented). |
